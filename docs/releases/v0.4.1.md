# QueryAssure v0.4.1 — Defense-in-depth for SQL Agents

QueryAssure v0.4.1 hardens the full path from model-generated SQL to CI evidence.

## Security improvements

- exactly one parsed read-only query per execution
- external DuckDB file, network, extension, and secret access disabled
- bounded query time, result rows, memory, temporary storage, and threads
- alias-aware, wildcard-aware restricted-column enforcement
- result-row and credential redaction in JSON and HTML reports
- fail-closed live model mode, optional bearer authentication, and bounded concurrency
- non-root, capability-dropped, read-only containers exposed only on loopback by default
- immutable GitHub Action revisions and Python/Node dependency security audits

## Upgrade

```bash
pip install https://github.com/Victoria824/QueryAssure/releases/download/v0.4.1/queryassure-0.4.1-py3-none-any.whl
```

Existing deterministic and offline workflows remain key-free. For a live reference API,
set both `QUERYASSURE_LIVE_ENABLED=true` and a strong `QUERYASSURE_API_TOKEN`, then send
the token as a Bearer credential.

QueryAssure remains an evaluation toolkit rather than a hostile-code sandbox. Public and
multi-user deployments should add an authenticated gateway and isolate SQL execution in
an ephemeral worker with least-privilege warehouse credentials.
